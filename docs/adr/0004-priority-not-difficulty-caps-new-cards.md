# 面试卡用重要度取代难度，并限制每日新卡引入量

面试卡没有 `difficulty` 字段。取而代之的是 `priority`（高频必答 / 常见 / 加分项），它同时承担两个职责：题库页的筛选维度，以及智能队列中新卡的引入顺序。面试题集还设有每日新卡上限（默认 15 张），`DailyStat` 为此新增 `newIntroducedCount` 字段。hot100 题集保持原有行为，不设上限、新卡按数组顺序引入。

去掉难度的理由：面试题没有客观难度标尺，手工标注的难度与 `easeFactor` 表达的是同一件事，而 `easeFactor` 是从真实表现学出来的，比手标更准。面试准备真正缺失的维度是"这题会不会被问到"。

设上限的理由：不加限制时首日会引入几十张新卡，它们在次日同时到期，形成到期雪崩；两周后面对"今天 200 张待复习"的用户会直接放弃，这是间隔重复系统最常见的死法。上限把引入速度压到可持续，而 `priority` 排序保证有限的额度先花在会被问到的题上。
