## §1 逐句细节备注

### S1 场景句

> 原文：我在做一个政务"边聊边办"场景的 AI 办事助手训练项目——用户跟助手边聊天边把事办完，比如提取公积金。这本质是对话驱动的工作流决策：模型要追问缺的信息、按合规顺序调工具、该拒办时拒办。

**备注 1.1 四个事项要能脱口而出（按难度递进记忆：查询→租房→购房→贷款）**
- 账户余额查询（最简单）→ 租房提取 → 购房提取 → 贷款还款查询（最难），难度 ⭐ → ⭐⭐⭐⭐。
- 记忆钩子："钱在哪"（查）→ "取小钱交租"（租房）→ "取大钱买房"（购房）→ "欠的钱怎么还"（贷款）。
- 为什么选公积金：规则明确、办没办成能用数据库状态程序化验证、四个事项同构且难度递进——适合先跑通"可验证、可审计、可扩展"的训练方法闭环。
- 追问"为什么不做万能政务助手"→ 目标不是产品，是方法：先在单事项上证明闭环有效，再按统一规范扩展（B2）。

**备注 1.2 "对话驱动的工作流决策"——记住四类目标失败模式**
1. 缺参数时靠猜而不是追问；
2. 工具调用时机或参数错误（例：没核身份就提交）；
3. 办完事遗漏必须告知的内容（例：不说处理时效）；
4. 该拒办、该转人工时硬着头皮办。
- 记忆钩子："问、序、告、拒"（追问 / 顺序 / 告知 / 拒办）。这四个正是通用大模型直接做会踩的坑，也是沙箱和 reward 要针对的目标（B1）。

### S2 做法句（一句话 = 一个模块，追问时逐个展开）

> 原文：做法是先把范围冻结在公积金的 4 个事项上，自建了一个模拟政务系统的沙箱环境；然后搭了一条全合成的数据管线；分别训练了办事模型和一个冻结的用户模拟器；设计了一套可以程序化验证的打分规则——办成没办成看数据库最终状态，该告知的话说到没有用语义判定；最后在这个闭环上做强化学习（GRPO）。

#### 2.1 沙箱环境

**备注 2.1.1 沙箱是"通用引擎 + 插件"，本身不含任何公积金知识**
- 引擎负责：按任务初始化数据库 → 校验每次工具调用的前置条件 → 执行或返回错误码 → 结束时导出数据库终态。
- 公积金业务全部以插件形式注册（政策规则卡、接口规格、标准操作链）。记忆钩子："引擎是跑马场，业务是租户"。
- 结构性拦截示例：跳过核身直接提交 → 引擎层直接拦下返回错误码；核过 A 的身份不代表能操作 B 的账户（前置条件绑定到具体主体，跨主体过不了）。

**备注 2.1.2 错误码三档（追问"怎么防违规操作"时的核心）**
- 硬违规（本轮直接零分）：调不存在的工具、调没权限的工具、模型输出协议级失败。就这三类。
- 效率错误（记失败调用、扣效率分、对话继续）：参数写错、前置没满足、参数层格式错——agent 看到报错可以自我修正，改对了仍能拿满分。
- 业务逻辑拒绝（**不罚 agent**，共 14 种）：资格不符、金额超限、账户冻结等——这是沙箱正确工作的结果，agent 该做的是向用户解释。
- 记忆钩子："三档 = 做了不该做的事 / 做对的事但方式不对 / 环境正常拒绝"。
- 语义型违规（真把没核身的写入落库）在这套结构下产生不出来，所以根本不建终态违规扫描器——这是死代码（F2）。

#### 2.2 全合成数据管线（五步）

**备注 2.2.1 五步流程**
1. 任务工厂按分布采样用户背景和业务参数；
2. 在沙箱里跑一遍标准操作链，**自动算出数据库目标状态（零人工标注）**；
3. 用一个更大的模型当老师生成候选对话；
4. 校验管线多层过滤（语义判定 + 信息泄漏检测）；
5. 任务有效性硬门，不合格直接拒绝入库。
- 记忆钩子："采样 → 自动算标准答案 → 老师生成 → 过滤 → 硬门"。

**备注 2.2.2 规模与两个诚实细节（C3 口径，追问"数据质量"时的弹药）**
- 发布训练语料约 4,000 条，实际训练 3,840 条。
- 诚实细节一（信号饥饿）："明确拒绝"类样本完整语料只有 54 条 ≈ 1.3%，其中真正承担身份冒用信号的只有 30 条、还只有两个字面模板（"我冒用他身份…"×20 + "我帮我父亲办…"×10）——这类任务表现弱有真实的数据原因。
- 诚实细节二（防线没接线）：历史任务里有 247 条被后来的有效性门退役——校验代码其实早就写好了，但一直没接进生成流程（§4.3 展开）。

#### 2.3 两个模型

**备注 2.3.1 办事模型 vs 用户模拟器**
- 办事模型 = 被训练的策略：Qwen3-4B + LoRA。
- 用户模拟器 = 另一个 4B，单独训练、**达标后冻结**再接进 RL。冻结原因：它是环境的一部分，如果它跟办事模型一起变，打分信号就被污染了（C5）。
- 模拟器五项验收全过：指令遵循 98.9%；信息释放时机（"不问不说"）98.1%；人设一致 91.0%（贴线）；过早结束、跑题都是 0。残余 1.9% 泄漏集中在"延迟披露"场景，持续监控不阻断。
- 追问"为什么模拟器不看工具返回"→ 群众看不到工作人员在哪个系统查的、返回的 JSON；模拟器只看自然语言对话，否则 agent 会学到"调了工具就行、不用好好说结果"（C1/F3）。

#### 2.4 程序化打分规则（reward）

**备注 2.4.1 当前第三版公式（C4 口径，能默写）**
- 硬违规 → 直接零分；
- 否则：完成度 × 0.65 + 告知合规 × 0.35 − 轮数惩罚 0.10 − 工具失败率惩罚 0.10。
- **关键设计：完成度 = 状态分 × 收尾动作分**——数据库状态对了但收尾动作选错（该转人工却硬着头皮办结）完成度直接是零。这是修上一版的真实漏洞（旧版"状态对但动作错也能得分"，导致稀有动作没有梯度）。
- 追问"为什么要 12 个格子"→ 4 事项 × 3 种收尾（办结 / 转人工 / 明确拒绝），判定和评测都按格来。
- 分项信息源互相独立：完成度读数据库快照、告知判定读模型说的话、效率惩罚读错误日志和轮数——一项被钻空子不直接污染其他项（reward hacking 防线之一，C7）。

#### 2.5 GRPO（算法口径要准确）

**备注 2.5.1 准确口径（C6）**
- 用的是 GRPO 风格**组内相对优势**：同一任务采样 8 条对话，组内互相比较谁好谁坏，不需要价值网络——对双 4090 是刚需。
- 框架实际优化的损失函数是 token 级 CISPO，**严格说不等于教科书原版 GRPO**；严格同策略设置下它的裁剪几乎不触发、行为接近原版——这是口径澄清，不是我们跑过的对比实验。
- 组内相对的已知风险：零方差组（一组全对或全错）没有学习信号，训练时这类组被丢弃。
- 追问"那怎么保证有信号"→ 训练前的可学性门槛：每条任务独立采样 8 次，成功 2–6 次说明组内有对比、可学；全败或接近全对的缺对比信号（§4.5）。

### S4 结果句（逐段展开，这是被追问最密集的地方）

> 原文：结果上诚实说：基础训练后，按数据库状态、收尾动作、该告知的话三项全对的最严口径，成功率约 80%；强化学习在没参与训练的保留测试集上，把"转人工"类任务提升了 9.2 个百分点、统计检验显著；但全任务面的提升还没证明——中途我发现评测面被一批本身就有缺陷的任务污染了，定位根因后重建了任务质量门，现在新任务集已生成冻结，可学性测试在收尾，长程训练还没开始。

#### 4.1 "成功率约 80%"

**备注 4.1.1 精确口径（D1）**
- 现役是 4B 的 SFT checkpoint（记忆锚点：ckpt720），统一评测下三项全对成功率 **80.1%**、硬违规 0。
- 分事项：账户查询 100%（满分）、租房提取 82%、购房提取 77%、贷款类最弱 61%。
- 分收尾：办结 84.5%、转人工 93.5%、**明确拒绝只有 20%**——最弱格，正是后来 RL 重点补的方向。
- 历史插曲（可选讲）：早期 8B 的评测报告后来被判定是旧评测代码的产物、数据污染，作废重测 8B 是 77.6%——这也是最终选 4B 的底气之一（E1）。

#### 4.2 "转人工提升了 9.2 个百分点、统计检验显著"

**备注 4.2.1 精确数字（D2 锚点 + G5-6）**
- 场景：S1 干净保留测试集（176 条保留题，**未参与训练**）上，转人工类 69.74% → 78.95%，**+9.21 个百分点**。
- 统计口径：比较单位是**配对差**（同一个任务 RL 后减 RL 前，消掉任务难度差异）；置信区间用**按题目家族聚类的自助法**（同族任务共享骨架词表、互相相关，不能当独立样本）；结果家族聚类 CI = [+3.29, +15.13]，整体在零以上。
- 纪律：整套分析预先注册、只看一次，不许"看一眼不理想换个切法再看"（防多重比较）。
- **同一个实验的安全面 caveat**：硬违规 3/1408 → 7/1408（+0.28pp）——"安全不降级"没有被证明，面试要主动说。

#### 4.3 "评测面被一批本身就有缺陷的任务污染了"（你点名要补的细节）

**4.3.1 污染的是什么任务——两类，记两个画面**

| 类别 | 期望行为 | 缺陷画面（为什么无解） |
|---|---|---|
| A. 冻结 × 贷款查询 → 转人工 | 账户冻结时转人工 | 工具层**没有任何一个工具能查到冻结状态**；政策卡里也没这条转人工规则；模拟器被设定"不问不说"。一个完美 agent 也必得零分 |
| B. 身份冒用 → 明确拒绝 | 检测冒充并拒绝 | "冒用"标记**只写在元数据备注里，没接进对话**——用户开场是正常第一人称、报的是真户主身份证号、核身恒通过。题面让模型检测一个不存在的东西 |

- 记忆钩子：A = "标签说要升级，但环境里根本没有能证明该升级的证据"；B = "标签说要拒绝，但对话里根本没有冒用发生"。
- 出处：Note 031 §3.1/§3.2、Note 030 P1；追问到代码层可以说：贷款任务的参考链直接复用了租房提取的链（缺观测步），对照组余额查询的链里有"账户冻结"报错观测步——对照组写法是对的，贷款任务抄错了。

**4.3.2 为什么说"测的是任务生成器，不是模型"——实证数字**
- 把 24 条桥接任务每条跑 8 次：工具返回里出现"冻结/封存"的次数 = 0；用户主动提出转人工的次数 = 0；期望转人工的那组实际 93 次办结 / 1 次转人工；期望拒绝的那组 94/94 全部办结。
- 结论：**模型按政策卡做的是"正确"的事，标签是错的**。"模型固执不升级/不拒绝"的叙事不成立（Note 031 §3.3）。
- 无效任务全部落在"0 分墙"上：38 条结构性坏任务 SFT 与 RL 后都是 0/304；拆掉坏任务后，剩下的真难任务从 14/288 → 25/288，几乎翻倍——方向一致，说明 RL 其实在迁移（这个反转很能打）。

**4.3.3 数字盘点（跨任务池有重叠，不能加总——D3 明示过）**
- 桥接任务集 24 条：**全数无效**（12 条冻结×贷款 + 12 条幽灵冒用）。
- 新合成的困难集：390 池里 42/50 无效（16 冻结×贷款 + 25/26 幽灵）；被拿去当"promotion 面板"的那 47 条里 41 条无效。
- 历史困难训练集 300 行里 **72 条无效**（52 幽灵 + 20 冻结×贷款不可观测）。
- 全量退役：**247 条**历史任务按哈希退役（162 幽灵 + 85 冻结不可观测），另加 28 条历史冻结请求。
- 关键干净面：训练分布内的复测面板 80 条 **80/80 有效**、175 条可训练池 0 无效——**所以 RL 训练信号本身是干净的，被污染的是评测面**（这条要主动讲，防止面试官误以为训练也脏了）。

**4.3.4 定位到的根因（一句话版本）**
- **防线存在，从未接线**：校验规则（invariants registry）早就写好了，但任务校验函数从来不运行完整注册表——规则形同虚设；真正的对抗注入机制也存在，但桥接/补充生成路径绕过了它直接调任务工厂；参考链验证器只验"可执行 + 没写库"，遇到提前终止的伪终局直接跳过。
- 缺陷从 Phase 2 就存在，但 Phase 2 从没生成过踩雷组合，Phase 6 是第一次踩中——所以拖到 RL 阶段才爆炸。
- 出处：Note 031 §3.2/§3.3、Note 030 §3；这是 A4/D5 的叙事核心，务必能独立复述。

#### 4.4 "重建了任务质量门"

**备注 4.4.1 质量门 = 五个硬问题（G4-7 的成熟表述，照背）**
> 一条任务想进训练或评测面，先过五个拷问，任何一个答不上来就出局：
> 1. 正确答案有可观测的证据吗？
> 2. 这个证据用允许的工具/对话真的拿得到吗？
> 3. 政策卡支持这个终局动作吗？
> 4. 标准答案轨迹、环境状态、终局标签三者一致吗？
> 5. reward 真的能区分"做对"和"做错"吗？
- 对应到两个反例：冻结×贷款违反第 2、3 条（证据不可达、政策不支持）；幽灵冒用违反第 1、5 条（没有证据、reward 无从区分）。
- 两个反例正好映射 A 类/B 类缺陷，追问时闭环。

**备注 4.4.2 重建做了什么（S0 修复，五件事）**
1. **接线**：所有生成入口强制执行完整校验注册表，不通过就物理上不了池（fail-closed）；
2. **对抗注入落地**：冒用类任务必须真的把"第三方代办"写进开场白和结构化字段；
3. **新增动作-证据蕴含校验**：要求"标签必须有可观测证据支撑"本身变成一条硬校验；
4. **批量审计脚本**复扫全部存量任务池，产出逐条 valid/invalid 清单；
5. **CI 反例测试**：构造"标记冒用但开场无冒用"的任务，断言生成管线拒绝。
- 修参考链：冻结语义按业务判据重定（查询类冻结→不升级、正常告知；写入类冻结→转人工，且先让环境能报出冻结错误）。
- 出处：Note 030 §4 S0、ADR P5-T0；全仓 pytest 通过（2,331 passed）后才关闭修复门。

#### 4.5 "新任务集已生成冻结 / 可学性测试在收尾 / 长程训练还没开始"

**备注 4.5.1 新任务集（D4 口径）**
- 重新生成 **3,100 条**并冻结：训练 1,800 / 开发 300 / 最终保留测试 1,000；12 个格子配额精确；生成全程**零门槛放宽**；保留测试集与训练集题目家族隔离（一族只取一条，从源头消掉相关性对统计的影响）。
- 记忆钩子："1800 训练 / 300 开发 / 1000 只看一次"。

**备注 4.5.2 可学性探测（D4 + P5 board）——为什么叫"可学性"**
- 原理：对每条任务独立采样 8 次，成功 2–6 次 = 组内既有成功也有失败、有对比信号（可学带）；全败 = 死池；接近全对 = 饱和。**难度不是看成功率高低，是看有没有中间带**。
- Wave1（2,880 轮，三个多小时、零基础设施故障）：8 个"事项 × 稀有收尾"组合里 7 个落在可学带。唯一缺口 = 购房提取×转人工：简单档任务没有一条落中间带（6 条全败、2 条只对 1 次），中高档反而大多接近全对——两头分化。
- 缺口根因（能讲透）：该格子的简单档任务全是"用户主动要求人工"型，而 SFT 训练数据里这个触发零供给——模型把"用户要人工"当正常业务流走完直接办结，所以简单档反而全败；修复 = 换成"账户冻结"触发（试点已证可学）。
- 修复重测 80 轮：10 条新任务全部 8 次全对——模型能解了，但直接全对、仍没产生中间难度任务，所以当时（08-11）字面门槛还不能宣布通过，要等全量合并终判。
- **【2026-08-12 之后的最新进展，按面试日期取用】** 第二波 11,520 轮已跑完（约 12 小时 46 分、零裁判基础设施故障）；跨冻结合并终判 **8/8 组合全部通过**（购房提取×转人工 9 条可学、账户查询×明确拒绝 67 条可学）；T4 前置门全清，**长程训练等授权，还没开始**。如果面试晚于 08-12，A1 的"可学性测试在收尾"可以说成"可学性测试已完成、全组合通过"。

**备注 4.5.3 长程训练计划（只能当"计划"说）**
- P5-T4：约 500 步 / 约 32,000 轮采样对话 / 4–8 周；起点 = RL 之前的 SFT 检查点（ckpt720）——**不用**中间那个带安全损伤的 checkpoint（+1.70pp 硬违规、−1.56pp 格式，被正式挡在门外）。
- 成功判定标准是**事先注册**的（P5 五条）：总体显著为正；三个收尾各自 −5pp 非劣；8 个稀有格 ≥6 格下界 >0；12 格无一塌方；硬违规 ≤1%；裁判审计干净。最终在 1,000 条保留题上比较训练前后，只看一次。
- 成本口径：双 4090；裁判调用预算约 5.5 万次、人民币几十元量级（定价，不是已支出）。
- 追问"为什么起点不用 RL 后的 checkpoint"→ 那个版本有实测的安全+格式损伤，P5 判定它不能进正式面（ADR P5-T0 决策 4）。
