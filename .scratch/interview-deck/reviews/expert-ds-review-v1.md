## 二、分维度意见

### 1. 覆盖度：漏了三条主线，另有两处次要遗漏

- **训练难度阶梯 / curriculum 设计（最重的遗漏）**。G3 整组只有"采样分布"（G3-2/3/4），没有"训练顺序与难度阶梯"：L1→L3 ladder 的单调性要求（`NOT_ELIGIBLE_AS_MONOTONIC_LADDER` 这个 blocker 在 spec A8-3 和 v3 ADR §8 里被反复强调——purchase×FWR 的 ladder 问题"reward 修复解决不了，也不能单凭 reward 版本变化解除其 curriculum/route blocker"）。面试官从"C0→C15 怎么安排的"或"难度怎么递进"切入的概率很高，这是 G3 的空白。**应 ADD。**
- **contrast-pair 构造侧**。自述集明确把"contrast pair 构造"移到深挖卡候选（"数据合成深挖"），但深挖集只接住了训练编排（G2-1 混组问题），**没接构造本身**：boundary factor 怎么选、A/B 怎么保证"只差一个关键事实"、naturalized pair / entity-preserving（`entity_preserving/` 模块）防什么、评测层的 contrast-set bucket 怎么用。这是项目最锋利的差异化设计，漏掉可惜。**应 ADD（common）。**
- **reward 权重来源与敏感性**。"0.65/0.35/0.10 怎么定的？做过敏感性分析吗？"是 reward 设计面试最高频的追问之一。仓库里的诚实答案组织一下就是 3-4 个原子点：权重继承 v1 主比例约 2:1（v2 ADR §3.2）、R_escalate 0.05→0.10 是为边界信号、**无系统敏感性分析（算力约束，且 v2 与 sampler 同轮启用、归因不干净已书面承认）**。**应 ADD（common）。**
- 次要：Policy Card 的"三界"（policy_card 规则 vs policy_params 数值 vs API spec 参数）是真实面试官会挖的数据建模问题，可并入 G2-7 作一个 bonus 要点，不必单独立题；envelope 设计已被 F8/G1-7/G7-4 覆盖，L3 tagger 是执行细节，都不需要立题。
