## 1. 自我介绍稿

### 90 秒版（默认）

"我是孙玺晨，北航 NLP 方向硕士。职业主线是三段演进：**对话系统 → Agent 平台 → Agentic RL 后训练**。

最早在小冰做游戏 NPC 人格化对话，解决单卡承载十余位 NPC 的 serving 约束，用剧本 post-training 加角色 Prompt 替代多 LoRA 热切换，积累了 SFT/RLHF 的第一线直觉。

现在在数字郑州——阿里巴巴和郑州市政府的合资公司——做两条主线：一是**企业级 Agent 平台与运行时**，我主导设计了配置驱动的双执行路径、AG-UI 协议层、长任务沙箱和插件体系，支撑了 ChatBI、长任务、多模态问答等业务 Agent 上线；二是**任务型 Agent 后训练全链路**，从沙箱任务工厂、数据合成漏斗，到 SFT 加长程 GRPO，这个项目我独立负责，最终在 96 题测试集上把严格成功率从 SFT 基线的 54.3% 提升到 84.4%。

中间还交付过多模态文档检索和大模型私有化部署，覆盖英伟达和昇腾两种硬件。论文方面有一篇 NLPCC 一作，专利方面有三项第一发明人发明专利、两项已授权。

我今天最想展开讲的是任务型 Agent 后训练这个项目，尤其是里面的 Reward 设计和一次放弃 Async RL 的取舍。"

### 3 分钟版（面试官说"详细介绍下自己"时用）

90 秒版基础上扩三处（每处约 30 秒，说完即停，不继续展开）：

1. **小冰段补技术取舍**："当时的约束是单卡要承载十余位 NPC 且人设一致。业界直觉是每个角色挂一个 LoRA，但 2022 年的 serving 条件下多 LoRA 热切换的显存碎片和延迟抖动不可接受，所以我把世界观注入放到离线 post-training，线上单基座加角色 Prompt，这个方案后来平滑迁移到了 14B。"
2. **平台段补设计归属**："平台是团队共同落地，但核心架构设计——双执行路径、协议解耦、ChatBI 从固定 DAG 重设计为 ReAct Agent Loop、Orchestrator-Worker 多智能体协调——都出自我，落地成熟度我可以逐块讲清楚哪些已合入主干、哪些还是设计稿。"
3. **后训练段补方法骨架**："后训练这个项目最关键的是三件事：用数据库终态比对替代主观打分、用终态乘法门控防 Reward 投机、用 pass@k 而不是 pass@1 判断 SFT 何时可以进入 RL 阶段。硬约束违规率最终压到 0.26%，经过两轮独立双盲审计。"

### 主动排雷（自我介绍末尾可选）

- 被问"6 个 0→1 系统"：现场报清单——①任务型 Agent 后训练系统 ②Agent 平台运行时 ③ChatBI ④多模态文档 RAG ⑤开源 LLM 私有化推理体系 ⑥NPC 对话系统（系统≠项目，平台衍生的独立上线系统计入）。
- 被问"4 年+"：2022.07 小冰入职起算即为 LLM 后训练工作。

## 3. 口径红线卡（进场前 1 分钟扫一遍）

1. **96 题测试集**：从 300 条 dev 任务按 12 格分层抽取、训练中用于 steering 监控的面板，与训练集 family 隔离——**永远不称 held-out**。
2. **泛化**：T5 千题 final holdout 已建好执行器但**未执行**——永远不说"泛化已验证"。话术："训练监控面板上稳定提升，最终泛化评测未执行。"
3. **训练规模**（500 步 / 3.2 万 rollouts / 2 卡）只口头，被问就坦荡报，不主动提。
4. **vLLM 约 6 倍** = 诊断出 Triton LoRA kernel 慢路径悬崖后改 Merged serving **恢复**吞吐，不是凭空优化。这个取舍直接导致 Async RL 的机制冲突。
5. **GRPO vs CISPO**：简历 GRPO 指组内相对优势估计范式；实际 policy loss 是 ART 默认 token-level CISPO。被问 loss 主动说清。
6. **成熟度标注**：Agent Teams=design_complete 未实施；ChatBI ReAct 在参考分支；A2UI 是探索原型。动词：设计/确立/重设计/探索。
7. **禁词**：转段、管线、训服分离、数据平面、硬件线。
8. **数字口径速查**：+30.1pp（54.3%→84.4%，SFT 基线，96 题）｜ FWR 8.6%→80.5%（+71.9pp）｜ HV 0.26%（2/768 口头）｜ vLLM 250→1500 tok/s。

## 4. 风险清单（最容易被问倒的 15 个点，详见 expert-outline-fable51.md §五）

| # | 风险 | 一句话应对 |
|---|---|---|
| R1 | 96 题集性质/是否 held-out | 主动先定性：分层抽取的 dev 监控面板，family 隔离；T5 未跑 |
| R2 | +30.1 与 +7.8 并存 | 两个不同 run：15 步原型 vs 长程；任务池清洗前后；只有后者上简历 |
| R3 | HV 0.26% 分子分母 | 2/768 episode 级，均为格式协议错误、无越权；CI 上界 <1% |
| R4 | GRPO 还是 CISPO | 主动分层：优势估计范式 vs 实际 policy loss，手写 C04 对照 |
| R5 | vLLM 6 倍措辞 | 诚实框定为"悬崖修复"；价值在诊断，且它决定了 D2 的边界 |
| R6 | Async RL 被误读为不懂异步 | 先肯定异步主流与前提（多版本权重），结论限定在 Merged 约束内；追问再给 14 步压测数据 |
| R7 | 双盲审计谁审/终点审没审 | R3 评分反投机 + R4 模拟器保真，中期两节点执行均通过；终点未单独审 |
| R8 | 项目二个人 vs 团队/成熟度 | 每块主动标成熟度；设计出自我，落地靠团队 |
| R9 | ColPali 效果证据 | MaxSim 与存储代价必须盲写（C17）；效果只给定性与评测方法 |
| R10 | 昇腾适配深度 | 边界诚实：框架适配调优，不是写算子 |
| R11 | 小冰 RLHF 细节 | 讲流程与坑，不给无出处数字；顺势对比 GRPO（P4-10） |
| R12 | "6 个系统"/"4 年+" | 现场报六项清单；2022.07 起算 |
| R13 | 训练规模追问 | 口头直给：数百步、约 3.2 万 rollout、2 卡；规模不是卖点方法才是 |
| R14 | 专利 vs 项目是否矛盾 | 两条线各讲各的：专利讲拓扑自调节，平台在企业可控约束下选固定协调模式 |
| R15 | 冻结 Simulator 被 exploit | R4 审计四项 + 信息边界（不看工具结果）+ 承认单一 Simulator 分布局限 |
