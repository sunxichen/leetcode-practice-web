# Tickets: 面试问答题集（Interview Deck）

把 `.scratch/interview-deck/PRD.md` 拆成 14 张 tracer bullet 票。领域词汇见 `CONTEXT.md`，不可逆决策见 `docs/adr/`，技术方案见 `docs/interview-deck-design.md`。

工作**前沿**：任何阻塞项已全部完成的票。票 1 与票 7 都没有阻塞，可以并行起步；其余大致是一条线性链。

没有需要 expand–contract 的宽重构——签名变更的爆炸半径都很小，每张票内都能保持绿色。

---

## 注入当前时间并锁定现有调度行为

**What to build:** 一条可运行的回归锚点。现在的调度状态机与队列生成在内部直接读取系统时间，导致行为不可测；改为由调用方传入当前时间，未传时行为与之前完全一致。引入测试运行器，针对**当前实现**写出通过的测试，把今天的 LeetCode 题集调度行为固定下来。后续每一次重构都要靠这组测试证明"逐位没变"。

**Blocked by:** 无——可立即开始。

- [ ] 测试可通过一条命令运行，跑在 Node 下，不引入 DOM 测试基建
- [ ] 调度状态机与队列生成均接受注入的当前时间；不传入时结果与改动前一致
- [ ] 自评的 4 档 × 生命周期 4 状态共 16 条迁移各有断言，覆盖下一状态、下次到期时间、间隔与 EF
- [ ] 断言学习中的卡按"重来 < 困难 < 良好"的顺序排列到期时间
- [ ] 断言失手后进入补习、成功补习后回到短间隔而非折半
- [ ] 断言间隔上限与 EF 下限的钳制生效
- [ ] 断言智能队列的编织顺序：learning 逾期最前、复习逾期与新卡按 3:1 交织、learning 待到期的插回位置落在钳制区间内
- [ ] 断言"攻克最弱"的排序依据 EF 与失手次数
- [ ] 全部测试针对当前实现通过，未修改任何产品行为

## 调度参数对象化

**What to build:** 把散落在模块级常量里的调度标定值收成一个显式传入的参数对象（学习步长、补习步长、毕业间隔、Easy 间隔、Hard 与 Easy 系数、间隔上限、失手恢复间隔、EF 相关阈值，以及队列编织需要的每分钟卡片数、插回钳制上下界、每日新卡上限）。LeetCode 题集的取值与现有常量逐位相同，所以外部行为零变化。

**Blocked by:** 注入当前时间并锁定现有调度行为

- [ ] 调度函数接受参数对象，不再直接读取模块级常量
- [ ] 存在一份 LeetCode 题集的参数取值，逐项与原常量相同
- [ ] 上一张票的测试断言内容未被修改（只允许适配调用签名），且全部通过
- [ ] 参数对象的类型定义覆盖调度与队列编织两类参数

## 抽出会话引擎缝

**What to build:** 队列生成目前藏在学习页的 hook 内部，无法独立测试。把它搬到一个纯模块边界：给定卡片集、进度、调度参数、会话模式与当前时间，返回队列顺序；hook 只保留状态与副作用。这是三个测试缝里价值最高的一个，本次改动的全部高风险逻辑都从这里进出。

**Blocked by:** 调度参数对象化

- [ ] 队列生成是纯函数，位于 hook 之外，参数与当前时间均由调用方注入
- [ ] 智能队列、按维度筛选队列、攻克最弱、单卡四种模式的队列生成都通过这一个边界
- [ ] hook 不再包含队列排序或编织逻辑
- [ ] 队列行为测试覆盖编织比例、插回位置钳制、筛选排序（逾期优先、失手次数次之、id 最后）
- [ ] 用同一组固定输入验证 LeetCode 题集的队列结果与重构前逐位一致

## 题集配置概念落地

**What to build:** 引入**题集**配置这一概念：一个题集聚合了它的卡片数据源、调度参数、可选会话模式清单、卡片正反面渲染组件。注册 LeetCode 题集，学习页改为从配置读取这些内容而不是直接引用常量与组件。此票不改任何用户可见行为，是为第二个题集铺路。

**Blocked by:** 抽出会话引擎缝

- [ ] 存在题集注册表，可按题集标识取出配置
- [ ] LeetCode 题集的配置完整，包含数据源、调度参数、模式清单、卡面组件
- [ ] 学习页与队列生成均通过题集配置获取参数，不再直接引用调度常量
- [ ] 用户可见行为与改动前一致，既有测试全绿

## 按题集分键的进度存储

**What to build:** 复习进度改为每个题集一份独立文档（见 ADR-0002：现有归并逻辑是整份文档比时间戳、赢者全取，两个题集共用一份会在多设备下互相覆盖丢进度）。进度读写接口接受题集标识并按白名单校验，键名不再硬编码。进度 Context 从"单份进度"改为并行加载所有题集、按题集标识取用，写入只写对应那一份。这是全项目最坏失败模式所在，必须补齐归并缝测试。

**Blocked by:** 题集配置概念落地

- [ ] 每个题集一份独立的进度文档，键名按题集区分
- [ ] 进度读写接口接受题集标识，非法标识被拒绝而不是落到默认键
- [ ] Context 并行加载所有题集并按题集取用，写入只影响对应那一份
- [ ] 每日统计与连续天数成为题集内概念；会话总结文案标明所属题集
- [ ] 归并测试覆盖：本地较新时以本地为准并回写远端、远端较新时以远端为准、两侧皆空时产出初始结构、损坏的本地数据被安全丢弃而非抛错、旧字段结构迁移正确且幂等
- [ ] 归并测试断言不同题集的读写互不干扰
- [ ] 开工前先手动导出一份现有进度快照留底，完工后用它验证既有进度读取无损

## 抽出学习会话外壳

**What to build:** 学习页里那约 300 行纠缠着模式选择、队列推进、翻卡、自评、退出动画、会话统计与撤销的状态机，抽成与题集无关的会话 hook 加会话外壳组件，差异由题集配置注入。现有学习页改为薄壳。这是为了不把这个状态机复制第二份——它是本次改动最大的实际风险。此票不改任何用户可见行为。

**Blocked by:** 按题集分键的进度存储

- [ ] 会话 hook 与外壳组件不包含任何题集特定的判断
- [ ] 现有学习页是薄壳，只提供题集标识与路由相关处理
- [ ] 翻卡、四档自评、退出动画方向、会话统计、撤销、键盘快捷键、单卡深链、模式选择、空状态、会话总结的行为与改动前一致
- [ ] 完工后在 LeetCode 题集上手动实刷一轮，确认无回归
- [ ] 既有测试全绿

## 面试题库内容管线与深度学习基础题

**What to build:** 面试**卡片**的内容模型与生产管线，外加第一批真实内容。题库按**分类**分文件，构建时校验，坏数据在构建阶段失败而不是刷卡时白屏。同时产出一批不依赖用户项目文档的深度学习基础卡，让下一张票一落地就有真实内容可刷。此票与票 1-6 无依赖，可并行。

**Blocked by:** 无——可立即开始。若测试运行器尚未就位，本票自行配置，方式须与票 1 完全一致（同一个测试运行器、同一个测试命令名），以便两条线合并时不产生实质冲突。

- [ ] 面试卡片类型定义完整：id、问题、分类、标签、**重要度**、可选提示、答案（**要点**必填 3-6 条，可选展开叙述、代码片段数组、常见坑）、可选追问、可选互链
- [ ] 代码片段带自己的语言字段，不复用算法题的解法类型
- [ ] 题库按分类分文件，合并导出的接口与现有题目接口对齐
- [ ] 仓库内有 schema 文档：字段定义、覆盖各种字段组合的标准范例、可直接复制给 LLM 的生成 prompt
- [ ] 校验器是纯函数，返回可定位的错误列表，覆盖：id 重复、id 不符合带分类前缀的语义 slug 规范、分类或重要度取值非法、要点为空或条数越界、互链指向不存在的卡、代码语言不被高亮器支持
- [ ] 命令行脚本只是校验器的薄壳，并顺带生成首页所需的轻量摘要
- [ ] 校验与摘要生成串进构建脚本，不依赖包管理器的 pre 脚本钩子
- [ ] 故意塞入一张坏卡时构建失败并给出可定位错误；摘要过期时同样被检出
- [ ] 校验器测试：每类坏数据各有断言，合规题库返回空列表，摘要输出与输入题库一致
- [ ] 产出不少于 20 张深度学习基础卡，覆盖注意力机制、损失函数、优化器、正则化、训练稳定性等主题，其中至少 5 张带代码片段
- [ ] 每张卡遵守粒度硬规则：一次 1-2 分钟内可口述完，要点 3-6 条；超出的题拆成概述卡与深挖卡并互链

## 面试题集智能复习跑通

**What to build:** 第一条端到端可刷通的路径。面试题集的配置（含按 1.5 分钟一张标定的调度参数）、独立的学习路由、最小可用的卡面，以及要点数锚定的自评条。此票完成后即可用真实的深度学习基础卡开始复习。

**Blocked by:** 抽出学习会话外壳；面试题库内容管线与深度学习基础题

- [ ] 面试题集已注册，调度参数按方案文档的对照表取值（学习步长更短、插回窗口更窄、间隔上限更紧）
- [ ] 面试题集有独立的学习路由，现有路由与深链一律未变
- [ ] 卡片正面显示问题、分类徽章、重要度徽章、标签，以及常驻的要点数量
- [ ] 卡片正面不显示任何调度信息（间隔天数、学习步数）
- [ ] 卡片背面以要点列表为主体
- [ ] 自评条的四档按当前卡要点数动态标注命中区间：困难档下界为要点数的 0.4 倍上取整，良好档下界为 0.8 倍上取整，简单档要求全中且能流畅串成话
- [ ] 自评不需要任何额外点击即可完成
- [ ] 智能复习模式可完整走通：翻卡、自评、进入下一张、队列耗尽后显示会话总结
- [ ] 撤销、键盘快捷键、单卡深链在面试题集下同样可用
- [ ] 面试题集的进度写入自己那份文档，LeetCode 题集的进度不受影响

## 面试卡背面补全

**What to build:** 把背面从"只有要点"补成完整的复习材料：代码片段按声明语言高亮并可复制、多段代码可左右切换、常见坑、可折叠的展开叙述、可能的追问，以及跳转到互链卡片的入口。

**Blocked by:** 面试题集智能复习跑通

- [ ] 代码片段按自己声明的语言高亮，不再一律当作 Python，并可一键复制
- [ ] 一张卡有多段代码时可左右切换浏览，复用既有轮播交互（箭头与圆点），但不复用算法题的解法类型
- [ ] 常见坑与追问在背面呈现
- [ ] 展开叙述默认折叠，可展开
- [ ] 互链卡片有跳转入口，可从概述卡跳到深挖卡并跳回
- [ ] 提示按钮仅在该卡写了提示时出现，点击后显示方向指引而非答案内容
- [ ] 背面各区块在只有要点、无代码、无追问等各种字段组合下都渲染正常

## 队列规则：重要度引入顺序与每日新卡上限

**What to build:** 让有限的新卡额度先花在会被问到的题上，并杜绝到期雪崩（见 ADR-0004）。面试题集的新卡按重要度顺序引入，且每天引入量有上限；LeetCode 题集行为保持不变。

**Blocked by:** 面试题集智能复习跑通

- [ ] 面试题集的新卡按重要度排序引入（高频必答 → 常见 → 加分项），同级按 id
- [ ] 面试题集每日新卡引入量不超过配置上限
- [ ] 每日统计新增"今日已引入新卡数"计数，跨天重置
- [ ] LeetCode 题集仍无上限、按原顺序引入，其队列结果逐位不变
- [ ] 队列测试覆盖重要度排序与上限生效，包含"额度用尽后队列只剩到期卡"的情形

## 全量扫题模式

**What to build:** 面试前一晚集中冲刷的入口。**全量扫题**无视到期时间，按重要度遍历全部卡（可限定某个分类），自评照常写入调度。

**Blocked by:** 面试题集智能复习跑通

- [ ] 模式选择界面有全量扫题入口，可选择限定分类或不限
- [ ] 队列包含未到期的卡，按重要度排序
- [ ] 扫题过程中的自评正常写入调度，与其他模式一致
- [ ] 每日新卡上限不影响此模式（扫题是刻意的全量遍历）
- [ ] 队列测试断言未到期卡被包含且排序正确

**What to build:** 打开应用第一眼就知道今天该刷哪边。首页从直接跳转学习页改为两个**题集**入口，各自显示待复习数与新卡数（读那份轻量摘要，不引入完整题库）。导航随所在题集变化。

- [ ] 头部品牌位显示当前题集名并可点击返回首页；首页时显示应用名且不可点
- [ ] 会话总结的连续天数文案标明所属题集
- [ ] PWA 从桌面图标启动后落在首页，行为正常

## 面试题库页与查阅

**What to build:** 面试前"我当时准备的答案是什么"这个需求的专用路径。面试题库页支持按分类与重要度筛选，列表项可就地展开只读答案——这是**查阅**，与复习是两种行为，不写入任何调度状态。

**Blocked by:** 面试卡背面补全

- [ ] 面试题集有独立的题库路由，可搜索问题文本与标签
- [ ] 筛选面板参数化，面试题集下按分类与重要度多选筛选
- [ ] 语义筛选沿用：待复习、即将到期、易遗忘、未学
- [ ] 列表项显示重要度、分类、熟练度与下次复习时间
- [ ] 列表项可就地展开只读答案（要点、代码、展开叙述），复用背面的渲染
- [ ] 展开查阅**不写入任何调度状态**，展开前后该卡的进度完全一致
- [ ] 列表项另有独立的"去复习"入口，进入单卡自评模式
- [ ] LeetCode 题库页行为不变

## 项目类与技术路线类真实卡

**What to build:** 依赖用户提供项目文档、技术方案与笔记才能产出的那部分内容：项目深挖卡与技术路线取舍卡。按粒度硬规则拆解——"介绍一下你的项目"这类大题拆成一分钟概述卡（STAR 骨架）加若干深挖卡（为什么选这个方案、最大的技术难点、效果怎么量化、重做会怎么改），彼此互链。

**Blocked by:** 面试题库内容管线与深度学习基础题；以及用户提供项目材料（此票在材料到位前保持不可开工）

- [ ] 每个项目有一张一分钟概述卡，采用 STAR 骨架
- [ ] 每个项目有若干深挖卡，与概述卡双向互链
- [ ] 技术路线类卡聚焦取舍理由，而不是技术介绍
- [ ] 所有卡遵守粒度硬规则：一次 1-2 分钟内可口述完，要点 3-6 条
- [ ] 要点是可判定"说到没说到"的原子陈述，不是答案摘要
- [ ] 重要度依据真实面试中被问到的可能性标注
- [ ] 全部通过题库校验
- [ ] 实刷两天后回看：若要点粒度不合适，在此票内调整而不是等到批量生成之后
